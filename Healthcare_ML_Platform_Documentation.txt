WHAT IS THIS PROJECT
====================
A full stack machine learning platform built with Python Flask backend and React frontend.
It has three separate healthcare ML projects combined into one platform.
The backend serves predictions through a REST API and the frontend displays results through a web interface.
Both run locally on your machine. No internet connection or API keys required.


PROJECT STRUCTURE
=================
C:\HealthcareML_Platform\
    01_Notebooks\       - Jupyter notebooks where models were trained
    02_Data\            - Raw and processed datasets
    03_Models\          - Saved trained model files (.pkl)
    04_Backend\         - Flask API server (Python)
    healthcare-frontend\ - React web application


HOW TO RUN THE PROJECT
======================
Step 1: Open Anaconda Prompt
Step 2: Navigate to backend folder
        cd C:\HealthcareML_Platform\04_Backend
Step 3: Start Flask server
        python app.py
Step 4: Wait until you see "Running on http://127.0.0.1:5000"
Step 5: Open a second Anaconda Prompt
Step 6: Navigate to frontend folder
        cd C:\HealthcareML_Platform\healthcare-frontend
Step 7: Start React app
        npm start
Step 8: Browser opens automatically at http://localhost:3000

To stop: Press CTRL+C in both prompts


PROJECT 1 - PATIENT READMISSION PREDICTION

What it does:
Predicts whether a patient will be readmitted to hospital within 30 days after discharge.

Dataset:
Source: Kaggle - Hospital Readmission Prediction Dataset

- age
- length_of_stay_days
- num_diagnoses
- num_medications
- prev_admissions
- glucose_level
- bmi
- has_diabetes

- PR AUC:    0.8794

PROJECT 2 - DISEASE OUTBREAK DETECTION
=======================================
What it does:
Detects whether reported disease cases represent a normal level or an outbreak.
Forecasts expected cases for next 7, 14, or 30 days.

Dataset:
Source: WHO disease surveillance data (Kaggle)
Records: 36,500 rows
Date range: 2009 to 2018
Diseases: 10

Diseases covered:
1. Cholera
2. Diarrhoea
3. Ebola
4. Malaria
5. Marburg Virus
6. Measles
7. Meningitis
8. Rubella Mars
9. Viral Haemmorrhaphic Fever
10. Yellow Fever

Algorithms used:
- Prophet (Facebook) for time series forecasting
- Isolation Forest for anomaly detection

Model performance:
- Prophet MAE:      2.20
- Detection Rate:   100%
- Isolation Forest F1: 0.39

How detection works:
The model calculates a z-score by comparing reported cases to the historical mean and standard deviation.
Z-score above 2.5 = Outbreak
Z-score 1.5 to 2.5 = Watch
Z-score below 1.5 = Normal
Isolation Forest also runs independently and flags anomalous patterns.

Alert levels:
- Normal:   cases within expected range
- Watch:    cases elevated, monitor closely
- Outbreak: cases exceeded threshold, immediate action required

API endpoints:
- POST /api/outbreak/detect   - detect if cases represent an outbreak
- GET  /api/outbreak/forecast - get 7/14/30 day forecast
- GET  /api/outbreak/history  - get historical case data

Frontend features:
- Disease alert board showing live status of all 10 diseases simultaneously
- Disease dropdown with icons

- Date picker
- Seasonal risk indicator showing monthly risk calendar per disease
- Severity meter (circular gauge)
- Z-score, anomaly score, spike ratio, growth rate displayed
- Baseline vs current visual bar with threshold markers
- What-if slider to test different case numbers without API call
- Trend direction indicator with accelerating/decelerating detection
- 7-day trend analysis with tomorrow estimate
- Days since last outbreak
- Baseline statistics panel
- Recommended actions checklist
- 14-day Prophet forecast area chart with confidence bounds
- Threshold lines on forecast chart (watch and outbreak levels)
- Toggle between 7, 14, 30 day forecasts
- 14-day risk calendar grid colored by alert level
- Download forecast as CSV
- Historical cases area chart

- Download history as CSV
- Session history storing last 5 detections
- Copy report to clipboard

PROJECT 3 - HOSPITAL RESOURCE OPTIMIZATION
===========================================
What it does:
Forecasts bed occupancy for hospital departments.
Calculates required staffing per shift.
Calculates costs and compares to benchmarks.

Dataset:
Source: Kaggle - Hospital Bed Occupancy Dataset
Records: approximately 180,000
Departments: 3 (ER, ICU, General Ward)

Departments:
- ER (Emergency Room):    50 beds
- ICU (Intensive Care):   30 beds
- General Ward:           100 beds

Algorithm: Random Forest (separate model per department plus one global model)

Model performance:
- R² Score: 0.9993
- MAE:      0.17
- RMSE:     0.21

Models saved:
- resource_model      (global)
- resource_er_model   (ER specific)
- resource_icu_model  (ICU specific)
- resource_gw_model   (General Ward specific)
- resource_scaler     (feature scaler)

Staffing ratios used:
ER:           1 nurse per 3 patients,  1 doctor per 5 patients,  1 support per 8 patients
ICU:          1 nurse per 2 patients,  1 doctor per 3 patients,  1 support per 6 patients
General Ward: 1 nurse per 6 patients,  1 doctor per 10 patients, 1 support per 12 patients

Occupancy alert levels:
- LOW:      below 50%
- MODERATE: 50% to 75%
- HIGH:     75% to 90%
- CRITICAL: above 90%

Shifts:
- Morning:   6am to 2pm
- Afternoon: 2pm to 10pm
- Night:     10pm to 6am

API endpoints:
- POST /api/resources/forecast-beds - forecast occupancy for department and date
- GET  /api/resources/overview      - snapshot of all 3 departments
- GET  /api/resources/staffing      - detailed staffing plan

Frontend features:

- Clickable department cards showing occupancy bar, beds, cost, staff count
- Comparison to historical average with trend arrow

- Auto-refresh every 60 seconds with countdown timer

Forecast Tab:
- Department selector with current live occupancy
- Date picker with quick presets (Today, Tomorrow, Next Week, Next Month)
- Optional occupancy override input
- Circular occupancy gauge for forecast result
- What-if occupancy slider (instant calculation, no API call)
- Cost analysis cards (daily cost, monthly projection, cost per bed, saving vs max, benchmark comparison)
- Cost recommendation text
- Staffing breakdown table (nurses, doctors, support vs morning, afternoon, night shifts)
- Understaffed warning badges on roles

IMPORTANT NOTES
===============
1. Flask server must be running before opening the React app otherwise all API calls will fail.
2. Both servers must run simultaneously. Keep both Anaconda prompts open.
3. No API keys are needed anywhere. Everything runs locally on your machine.
4. Models are loaded into memory at startup. First load takes about 5 seconds.
5. The project does not use any database. Predictions are not saved permanently.
6. Session history in the frontend is stored in browser memory only. Cleared on page refresh.
7. The readmission model was trained on 9 features only. The clinical context fields
   (gender, smoking, insurance, diagnosis) are for display purposes only and do not
   affect the prediction.
8. Outbreak history data covers 2009 to 2018 only. Forecast dates are relative to that range.

ABOUT THIS PROJECT
==================
Healthcare is one of the most data driven industries in the world. Hospitals generate
massive amounts of patient data every day but most of it goes unused for decision making.
This project uses machine learning to turn that raw data into actionable predictions that
can help doctors, nurses, and hospital administrators make better decisions.

The Healthcare ML Platform solves three real world problems that hospitals face daily.

Problem 1: Patient Readmission
When a patient is discharged from hospital there is always a risk they will return within
30 days due to complications. Each readmission costs the hospital money and more importantly
it means the patient did not recover properly. By predicting which patients are at high risk
of readmission before they are discharged, doctors can take preventive action like scheduling
follow up appointments, arranging home care, or keeping the patient longer.

Problem 2: Disease Outbreak Detection
Disease outbreaks like Meningitis, Cholera, or Malaria can spread rapidly if not caught early.
Health officers receive daily case count reports but it is difficult to know if a spike in
cases is just random variation or the beginning of an outbreak. This platform uses statistical
analysis and machine learning to automatically flag when case counts are abnormally high and
tells the health officer exactly how serious the situation is and what actions to take.

Problem 3: Hospital Resource Optimization
Hospitals struggle to manage beds, staff, and costs efficiently. Too many staff scheduled
means wasted money. Too few staff means patients do not get proper care. This platform
forecasts how full each department will be on any future date and automatically calculates
exactly how many nurses, doctors, and support staff are needed per shift and what it will cost.

Who would use this platform:
- Doctors and nurses: check patient readmission risk before discharge
- Hospital infection control officers: monitor disease outbreaks in real time
- Hospital administrators: plan staffing and budget based on predicted occupancy

This is a complete end to end machine learning project. The data was collected from Kaggle,
models were trained in Jupyter notebooks, a REST API was built in Python Flask to serve the
predictions, and a React web application was built to display everything in a professional
dashboard interface.
